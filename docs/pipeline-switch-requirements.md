# 采集管线切换需求

## 目标

在 V-RSS 中提供一个全局、可持久化的采集管线选择：

- 方案1：通过 `PLATFORM_URL` 指向的 `.xyz` 微信读书采集服务获取公众号信息和文章。
- 方案2：通过本项目自有的微信公众号后台登录、搜索和 `appmsgpublish` 接口获取文章。

当当前方案受到限流或不可用时，用户可以在公众号源页面手动切换到另一方案。服务重启后保持最后一次选择。

## 功能要求

1. 默认使用方案1，以保持当前工作树的既有行为。
2. 当前方案存入数据库，不能只保存在浏览器或服务内存。
3. 账号必须记录所属方案，两个方案不能互相使用对方的 token。
4. 登录二维码、登录结果、添加账号、获取公众号信息、拉取最新文章和拉取历史文章都必须使用当前方案。
5. 方案1拉取文章时使用 `Feed.id`；方案2拉取文章时使用 `Feed.fakerId`。
6. 订阅源缺少当前方案需要的标识时，返回明确错误，不能静默返回空文章。
7. 正在执行“更新全部”或历史文章任务时禁止切换，防止同一任务中途跨方案。
8. 页面显示当前方案、两种方案说明，并提供明确的切换操作。
9. 切换后刷新采集状态、账号列表和相关查询缓存。
10. 限流状态只约束当前方案；另一方案可供用户切换使用。

## 验收标准

- API 能查询当前方案并在 1/2 之间切换。
- 重建服务实例后仍能从数据库恢复已选方案。
- 方案1调用 `WereadService`，方案2调用 `MpService`。
- 方案2使用 `fakerId`，不存在时返回可理解的错误。
- 两种方案只选择各自账号。
- 前端可看见并切换方案，切换期间有加载态和结果提示。
- 后端、前端构建通过；新增管线路由测试通过。

## 非目标

- 本次不实现自动故障切换，避免一次失败导致不可控地消耗另一方案配额。
- 本次不改变微信上游的限流参数和恢复规则。
- 本次不保证非公开上游接口具备服务等级承诺。
